# Step 05E 中文學習筆記：感測異常候選的人工回查與 OCAP

## 01 這一步真正要回答什麼？

前面已經找出 11 片晶圓的感測異常候選，並確認它們的 MRR 都落在相應參考群體的 Q05～Q95 內。這種情況下，工程師該怎麼辦？**不能直接宣布設備故障，也不能因為 MRR 沒超過 Q05/Q95 就把感測器的警訊忽略。**

本步的目標是將 **同一片晶圓、同一匿名代碼**下的觸發訊號、參考區間與量測品質整理成一份可交給工程師調查的紀錄。

## 02 相關名詞（白話）

| 名詞 | 白話意思 | 不能誤解成 |
|---|---|---|
| FDC 候選 | 與這個代碼的參考感測訊號不相似，值得查看 | 已證實設備故障 |
| Q01 / Q99 | 前段參考樣本中，第 1 / 99 百分位數 | 已核准工程上下限 |
| MRR Q05 / Q95 | 前段品質資料的描述性區間 | 合格與不合格的判定標準 |
| OCAP | 超界或異常後預先定義的應對流程 | 本程式已執行停機或調整參數 |
| 根因 | 造成品質或設備問題的實際原因 | 只靠訊號一起偏離就能證明 |

## 03 個案示範：WAFER_ID = 33494120 / Code 6

在已凍結的 Step05C 參考下：

- Retainer pressure 活動時典型值為 **741.0**，低於該匿名代碼的 Q01 **1306.929**。
- Slurry Flow A 活動時典型值為 **14.652778**，高於該代碼的 Q99 **8.138889**。
- 同一片晶圓的 MRR 為 **74.68125**；所屬 Codes4–6 參考 Q05～Q95 約 **57.9475～81.6890**。

**可以說：** 同一匿名代碼下至少兩類感測指標偏離凍結的參考分布，但這次的 MRR 沒有超出描述性參考區間。

**不能說：**「研磨液流量過高造成壓力下降，機台故障但良率沒受影響。」目前沒有工程規格、實際控制參數、故障標籤或因果證據。

## 04 排查順序（面試白話版）

1. 確認晶圓、匿名代碼、時間戳及原始感測紀錄是否對得上。
2. 確認感測數值的單位、零值意義、是否有校正或資料品質問題。
3. 若現場資料可取得，查看相同配方／通道的壓力與研磨液歷史波形、耗材變化、設備維修事件。
4. 比對製程後量測與**真正的工程規格**，不是用資料的 Q05/Q95 宣稱合格。
5. 把疑點與證據交由製程／設備／品質工程師評估，依內部已核准 OCAP 決定是否量測確認、hold lot、調整等。
6. 保存處理記錄與後續驗證結果；本作品並沒有真實執行這些工廠操作。

## 06 為什麼這樣能連到後續工作？

目前 FDC 的探索工作提供的是 **問題篩選與排查線索**，但 11 個候選的 MRR 都在 Q05～Q95，而 77 個非候選落在區間外。若下一步要回答「能否從製程數據預測最終 MRR」，就需要建立**虛擬量測（Virtual Metrology）迴歸模型**，而不是拿 05C 的候選標籤直接當品質預測真值。

下一階段先規劃：凍結 Stage A 代碼分組、僅從 Training 建立晶圓層級感測特徵、制定同晶圓分組驗證與極端值敏感度報告，再比較簡單基準與機器學習模型。不能一上來就報測試集分數。
