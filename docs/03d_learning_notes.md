# Step 03D — SPC 之前的時間順序與代碼完整性檢查

## 這一步的工程問題

我們已發現 Stage A 的 MRR 有兩種水準，Codes 1–3 與 4–6 各自也有連續升降。然而，**連續紀錄並不一定是工廠連續加工的不同批次**。如果時間排序、觀測單位、設備分組都還不明確，就直接繪製管制圖，警報未必有工程意義。

## 逐一解釋

1. **Machine-code signature（代碼組合）**：檢查同一個 wafer-stage 的感測紀錄是否包含預期的 `1,2,3` 或 `4,5,6`。有些只有單一代碼，不能悄悄混入正常完整三通道樣本。
2. **Recorded span（紀錄跨度）**：最後時間減最早時間，不保證等於真正的機台加工時間（可能有停機、等待或資料合併）。
3. **Adjacent overlap（相鄰時間區間重疊）**：目前這片的第一個時間戳早於前一片最後的時間戳。它提示排序不是單純的一片做完下一片開始，**不表示資料錯誤或一定同時加工**。
4. **Lag-1 correlation（相鄰資料相關）**：前一片與下一片的 MRR 是否呈正相關。沒有確定的加工順序時，只能描述目前排序資料的特性。
5. **Phase I SPC（建立基準前的穩定性評估）**：建立 CL／UCL／LCL 前應有同質、可追溯、足夠穩定的參考資料。我們尚未驗證這些條件，因此目前不算正式管制界限。

## 輸出的表格

- `03d_code_signatures.csv`：各組設備代碼有哪些、各多少筆。
- `03d_incomplete_code_signatures.csv`：與主要代碼組合不同的樣本，先保留待查。
- `03d_time_structure_by_group.csv`：感測時間跨度、相鄰重疊、時間間隔等彙總。
- `03d_adjacent_wafer_intervals.csv`：逐對紀錄的開始、結束、重疊秒數，可回查。
- `03d_long_duration_review.csv`：跨度大於該組中位數 10 倍的待查資料；**這不是製程時間規格**。
- `03d_notes.json`：方法與限制。
- `figures/03d_machine_code_signatures.png`：代碼完整性圖。
- `figures/03d_recorded_time_span.png`：紀錄時間跨度分布圖。

## 確認後下一步

如果時序基準仍有不確定性，先設計以晶圓階段為獨立觀測單位、避免數據洩漏的候選監測策略，必要時使用訓練集的時間區塊或同質子群做探索性 Phase I；不聲稱是工廠驗證的正式 SPC。R2R 控制仍另以模擬展示。
