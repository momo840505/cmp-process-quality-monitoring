# Step 05A：FDC 感測資料盤點（學習筆記）

**FDC** = Fault Detection and Classification（故障偵測與分類）。真實工廠會分析機台在加工期間的壓力、轉速、研磨液流量等訊號，尋找偏離經驗或工程設定的情況，並調查可能原因。

在建立警報前，先檢查資料的訊號語意，避免誤把某段機台的非作用區間當成異常。

## 本步驟名詞

| 名詞 | 白話意思 | 為什麼要算 |
|---|---|---|
| `MACHINE_DATA` | 公開資料中的匿名通道／位置代碼 | 不同代碼可能有不同訊號記錄方式 |
| Nonzero fraction（非零比例） | 有多少感測資料不是 0 | 找出某通道在哪些時段有數值；**不能推斷 0 一定是故障** |
| Event-weighted | 每一筆感測紀錄算一票 | 長時間紀錄的晶圓會影響較大 |
| Wafer-channel-weighted | 先為每個晶圓每代碼計算，再做彙總 | 避免把一片有幾百列的晶圓當成幾百片 |
| Median（中位數） | 排序後位於中間的數值 | 比平均數不容易被極端值拉動 |

## 讀圖

**熱圖**：每一列是一種感測器，每一欄是不同匿名代碼，顏色及數值是各晶圓在相應代碼的非零比例中位數。數值越大，代表較多紀錄不是 0，並非機台品質越好。

**示例晶圓波形圖**：這是為了畫面可讀性，從三項選定感測器皆有一定活動比例的晶圓中挑選，不是隨機抽樣或典型晶圓。三個小圖是壓力、研磨液流量、晶圓轉速。X 軸在各代碼內獨立縮放為 0～1，這樣便於比較形狀，但不是實際秒數，也不能推定三條線同時發生。

## 面試時可以怎麼說？

「我先把製程感測資料按匿名設備代碼分開檢查，發現各代碼的非零訊號比例和時間型態不同，所以我沒有直接用所有數據建立一組 FDC 警報門檻。這一步是辨認可比較的感測資料，不是在宣稱已發現故障。」
