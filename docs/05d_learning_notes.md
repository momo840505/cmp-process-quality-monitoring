# Step 05D 學習筆記：感測數據偏差，真的造成品質不好嗎？

## 1. 我們為什麼做到這一步？

Step 05A：檢查哪些訊號在各代碼有活動；Step 05B：檢查訊號「非零比例」；Step 05C：比較非零時的「典型數值」並凍結多類訊號異常候選。現在才可以讀取最後 MRR，檢查是否同時偏離。

- **FDC 前半段：** 從機台訊號找出值得調查的紀錄。
- **品質結果：** 實際測得的 MRR。要先量測完成才能知道，不是機台當下就已經提供的標籤。
- **SPC：** 詢問隨時間的品質數值是否存在特殊原因變異。不能隨意用 q05/q95 冒充 SPC 管制界限。

## 2. 為什麼要把三個機台代碼「合成一片晶圓」？

例如 `WAFER_ID=123` 同時有 Code 4、5、6，但這片晶圓在 Stage A **只對應一筆 MRR**。它不應該被當成三片獨立晶圓。因此我們先把 Step 05C 在各代碼的 sensor-only 標記合併為 wafer-level 的 `sensor_candidate`，再把一片晶圓連到一筆 MRR。

## 3. 為什麼只用 Training？

Step 05C 在 Training 中先使用前段 60% 建立感測參考範圍，後段 40% 找候選。在 Step 05D，我們只對 **同樣的 Training Stage A 後段 468 片** 做探索性結果對照。不能看 Test/Validation 的 MRR，再偷偷調整候選門檻。

## 4. 每個欄位代表什麼？

| 名稱 | 白話意思 |
|---|---|
| `sensor_candidate` | 這片晶圓在任何代碼上符合 Step 05C 預先設定的雙類別訊號偏差 |
| `AVG_REMOVAL_RATE` | Stage A 材料去除率（原資料尺度，非規格合格判定） |
| `reference_median` | 只用同組前段參考資料估計的 MRR 中位數 |
| `mrr_abs_difference_from_ref_median` | 這片的 MRR 與前段中位數的絕對差距 |
| `reference_q05`, `reference_q95` | 前段 MRR 的 5% 和 95% 分位點，僅用來描述 |
| `outside_reference_q05_q95_descriptive` | 是否超出上述描述區間；**不是**不良品、OOC 或正式 SPC 告警 |
| `frozen_sensor_evidence_json` | 具體哪個感測器偏高／偏低、當時數值與先前固定的參考範圍 |

## 5. 這次實際結果的意義

11 片都同時出現壓力與研磨液相關感測值偏離，但它們的 MRR 沒有超出組別的前段 5–95% 描述區間。

這可能表示：某些機台訊號雖然罕見，但不一定立即反映為當片晶圓的最終 MRR 偏差。也可能是我們沒有掌握真正的配方、設備狀態、品質目標、或感測器資料的完整意義。

**不能反過來說：**「所以機台完全正常」、「所以 Step 05C 沒用」，也不能為了產生好看的結果就修改原本的規則。

## 6. 面試回答的白話版本

「先用機台訊號建立不依賴品質答案的異常候選，再把候選晶圓和研磨後的 MRR 結果對照。最後有 11 片晶圓被感測值篩出來，但它們的 MRR 都沒有超出組別參考資料的描述區間。這告訴我，感測異常和品質不良不能直接畫等號。因為沒有工廠的真實故障標籤與規格，我會把它們列為優先回查，而不是宣稱設備故障。」
