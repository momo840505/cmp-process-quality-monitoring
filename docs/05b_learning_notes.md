# Step 05B｜建立依匿名代碼分開的感測活動參考範圍

## 這一步為什麼要做？

05A 發現，同一個感測器在 `MACHINE_DATA` 不同代碼下，其非零紀錄比例不同。因此不應將 Code 1～6 混在一起，用單一閾值宣稱故障。這次只分析「一片晶圓在某一個代碼內，感測紀錄有多少比例不為 0」，**不是壓力或轉速的原始數值大小**。

## 四個預先指定的感測特徵

| 特徵 | 中文意思 | 訊號類別 |
|---|---|---|
| `PRESSURIZED_CHAMBER_PRESSURE__nonzero_fraction` | 壓力非零紀錄比例 | pressure |
| `SLURRY_FLOW_LINE_A__nonzero_fraction` | 研磨液 A 非零紀錄比例 | slurry |
| `WAFER_ROTATION__nonzero_fraction` | 晶圓旋轉非零比例 | motion |
| `STAGE_ROTATION__nonzero_fraction` | 工作台旋轉非零比例 | motion |

*相同類別不應被當作多個獨立的故障證據。* 例如 wafer rotation 和 stage rotation 同時偏離，我們只算作 motion 一個類別。

## 步驟詳解

1. 使用 `05a_wafer_channel_signal_features.csv`，其內容只來自 **Training / Stage A** 的感測器資料，不涉及 MRR。
2. 依晶圓最早的感測紀錄時間，在 Codes 1–3、Codes 4–6 兩個大組各自排序；每片晶圓及其所有代碼保持在同一組。
3. 前 60% 晶圓叫 reference（供建立參考範圍），後 40% 叫 later（供觀察新資料），**不是已核准的正常與異常分組**。排序不等於經獨立驗證的工廠批次順序。
4. 在每個代碼內，只從 reference 中代碼完整、沒有同時間不同感測值衝突的晶圓－代碼紀錄估計第 1、50、99 百分位數；不碰 later 數值。
5. 如果該代碼特徵變動太少或有效參考筆數不足，標成「不適合本次活動比例篩選」，不要硬設界限。
6. 對後段資料檢查是否落在自身代碼的 q01～q99 之外。先列出任一訊號類別偏離的情形；當同一晶圓、同一代碼有兩種以上類別偏離，才列為較高優先的**待查候選**。
7. 原始特徵與所有品質疑慮紀錄保留；同時間不同值的紀錄標示 QA 風險，**不是自動刪除**。

## 怎麼讀結果？

- `05b_code_specific_reference_profiles.csv`：每個代碼在四個特徵上的描述性 q01／q50／q99，及是否足夠變動可比較。
- `05b_wafer_code_activity_screening.csv`：3496 筆晶圓－代碼逐筆標記及原因。這是查核來源。
- `05b_screening_summary_by_code.csv`：依代碼統計後段偏離數量。**不是故障率、真正的 SPC OOC 率或準確率**。
- `05b_later_two_family_candidates.csv`：如為零筆，代表目前的保守條件沒有觸發；不能說沒有故障。
- `05b_screening_method_notes.json`：方法與限制，面試說明要保留。

## 這份資料能證明什麼／不能證明什麼？

能證明：實際用感測紀錄建立代碼專屬的活動分布；參考與觀察段分開；零值與資料品質有明確標記；發現有哪些感測活動值得回查。

不能證明：代碼代表真正的不同機台、設備設置或 Recipe；零值表示異常或感測器壞了；任何候選是真實故障；參考段已經穩定且正常；百分位參考範圍是工廠核准 FDC 限值。

這個版本只監控非零比例，**還未監控有效加工期間的壓力、流量或轉速幅度**。後續 Step 05C 應先區分有活動區間，再分析訊號幅度與跨晶圓變化，避免「非零比例正常」就誤以為設備正常。
