# Step 07A — R2R 製程控制模擬：先建立「不調整」的比較基準

## 為什麼不能直接使用 PHM 資料做真實 R2R？

PHM CMP 資料提供機台訊號與 MRR，但沒有可核對的完整「上一批量測 → 調整製程設定 → 下一批量測」閉迴路紀錄，也沒有經證實的製程增益（調整旋鈕一單位，MRR 變化多少）。因此，這一階段另外建立**完全虛構的製程數學模型**，用來解釋控制策略，而不是還原 PHM 或 Micron 設備。

## 本階段的控制問題

假設設備每加工一次晶圓（一次 run）後，才收到 MRR 量測。製程會隨時間慢慢偏移，偶爾出現額外偏移。若機台一直保持同一設定值，最終 MRR 會不會逐漸遠離目標？Step 07A 先產生 120 次「不調整」的比較基準。

**所有數字均為示範假設**：MRR 目標 = 75、設定值 = 50、製程增益 = 0.65、漂移及雜訊也是我們自己設定。沒有真實工程單位或規格。

### 程式計算公式

```
actual_MRR[t] = 75 + 0.65 * (setpoint[t] - 50) + drift[t] + process_noise[t]
measured_MRR[t] = actual_MRR[t] + metrology_noise[t]
```

- `actual_MRR`：我們假想的實際品質；工廠一般無法直接看到「無誤差的真值」。
- `measured_MRR`：模擬量測儀實際回報的品質，也是將來 R2R 控制器**唯一能接收到的品質回授**。
- `drift`：模擬設備、耗材或環境變化帶來的偏移。真實原因未被本模型驗證。
- `process_noise`：模擬每次加工隨機差異。
- `metrology_noise`：模擬量測本身的誤差。
- `setpoint`：模擬「可調製程旋鈕」，不是 PHM 裡的任一真實感測器欄位。

在 Step 07A，`setpoint[t]` 每次都維持 50，表示**沒有 R2R 回授控制**。

## 後續的公平比較方法

Step 07B 設計控制器，Step 07C 才比較「開啟／關閉回授」。為了公平，兩種方法必須使用**完全相同的 drift、process_noise、metrology_noise**。控制器只應收到上一批已量測的 MRR，不能偷看真實漂移或未來雜訊。

**不要將本階段算出來的 MAE/RMSE 寫成真實工廠良率提升。** 它們只表示虛構實驗中，量測 MRR 與我們假設目標的距離。
