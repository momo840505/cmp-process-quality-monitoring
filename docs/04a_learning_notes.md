# Step 04A 中文學習筆記：第一次真正接觸 SPC I Chart

## 為什麼現在要做？

Step 03A 找到兩種 MRR 群體；03B 找到匿名 MACHINE_DATA 代碼組的對應；03C 看到前後時間相關；03D 又確認感測時間區間重疊，並不是可靠的單機逐片 run-to-run 順序。

我們現在要試做一張 **I Chart（單值管制圖）**，讓你直接看出：若忽略前提，管制圖會發生什麼事。

## 何謂一個點？

一個點 = 一片晶圓在 Stage A 的一筆 AVG_REMOVAL_RATE；不是一筆感測器取樣。

## 三條線是什麼？

- `CL`：參考段 MRR 的平均數。
- `MR`：前後兩筆 MRR 差的絕對值（Moving Range，移動全距）。
- `sigma_hat = average(MR) / 1.128`：在相鄰數值獨立且穩定等假設下，用 MR 估計單一點的標準差。
- `UCL = CL + 3 × sigma_hat`、`LCL = CL - 3 × sigma_hat`。

超過 UCL/LCL = **示範統計警報**。不是產品不合格，不是工廠正式 OOC，更不能把 UCL/LCL 當成 USL/LSL（規格限）。

## 為什麼 60% / 40%？

這是固定好的教學分段：前段暫時估線，後段檢查，避免用所有數據算完界限再回頭說後面數值都很正常。但 60% 並非最佳 SPC 樣本選擇準則，前段未確認穩定便不能稱正式 Phase-I 基準。

## 為什麼傳統 I-MR 對本資料有風險？

想像今天的 MRR 偏高，下一片也常常偏高。兩片數值雖然可能都離整體均值很遠，但彼此差距不大。以「前後差」算出的標準差會偏小，讓 UCL 和 LCL 太窄，產生許多超界點。

在 Step 03C 我們已量到相鄰 MRR 的相關係數：Codes 1–3 約 0.671；Codes 4–6 約 0.864（整組）。這不是因果證據，也不足以說明哪一個設備參數導致偏移。

## 這次特別保留的五筆

- Codes 1–3：4 筆 MRR > 1000。這是資料品質**檢查旗標**，不是確定錯誤或不良。
- Codes 4–6：1 筆只有代碼 4，資料模式不一致。它的 MRR 78.2805 並非極端數值。

不能偷偷刪掉這五筆後宣稱完整資料都符合統計控制。

## 看圖時的重點

1. 前 60% 的藍點是否已經有大量超界紅叉？若有，該「參考段」不具備可直接使用的穩定性證據。
2. 後 40% 的橘點超界數量有多少？它們只能說和**示範參考段**的統計界限不同，不能判定瑕疵晶圓。
3. 圖上的時間是最早感測時間排序，不是已經獨立驗證的逐片製造批次。
4. 這一步不看 Test/Validation，不設定真實工程上下規格，也不算 Cpk。
