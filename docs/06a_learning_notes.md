# Step 06A 中文學習筆記 — Virtual Metrology 的資料準備

## 1. 我們要解決哪個問題？

當晶圓 CMP 加工完成，但正式的研磨結果 MRR 還沒量測出來時，是否可以先使用加工期間已收集到的感測訊號，估計這片晶圓的 MRR？這稱為**虛擬量測（Virtual Metrology，VM）**。不是取代正式量測，而是探索能否更早提供品質風險線索。

## 2. 為什麼只有 1,166 筆，而不是 375,209 筆？

375,209 是 Stage A Training 的機台**時間點紀錄**。同片晶圓有多筆時間點，但只對應一個 Stage A MRR。因此建模單位必須是**晶圓－階段**：1,166 片 Stage A 晶圓 = 1,166 筆模型樣本。否則把同一片晶圓數十、數百筆時間點隨機分開，模型會偷看到同一片晶圓的資訊。

## 3. 怎麼把時間序列變成模型特徵？

例如同一片晶圓的 Code 4，在 Slurry Flow A 這個訊號有 100 次紀錄，其中 80 次非零；那麼 `nonzero_fraction=0.80`。把那 80 個非零值由小到大排序，取中間值，是 `median_nonzero`。

每種感測訊號都依 **MACHINE_DATA code** 各自計算；不同代碼的訊號不直接混在一起。另記錄各代碼事件數與耗材使用量中位數。

若訊號從頭到尾都為零，`median_nonzero` 保持空值（NaN），不是 0。零可能是沒活動，也可能是資料定義所致，不能自行判定。

## 4. 為什麼只用 Training？

原始資料有 Training／Validation／Test，但過去檢查發現不同資料組的晶圓 ID 有交疊。因此現在先只使用原始 Training Stage A，建立一個**以 WAFER_ID 為單位**的不重疊內部分割。這避免我們訓練與內部測試看見同一片晶圓。

`train` 用來學模型及所有補值/標準化參數；`valid` 用於選參數；`test` 保留作內部最後檢查，不能在看到 test 成績後不斷改模型。原始競賽 Test／Validation 暫時封存，之後再做外部評估。

## 5. 哪些欄位不能當模型輸入？

`AVG_REMOVAL_RATE` 是要預測的答案，不是輸入！`mrr_review_gt_1000` 是由答案計算出的標記；如果拿它當特徵，就相當於考試前把答案交給模型。`WAFER_ID`、`first_timestamp` 也不要當數值預測器。`code_signature`、資料品質檢查欄只做描述與稽核。

唯一允許進模型的，是 `06a_feature_catalog.csv` 的**特徵白名單**。即使白名單也不代表每一欄必須使用：下一階段仍需在 train 裡處理常數、缺失比例與共線性。

## 6. 為什麼先不計算 RMSE 或 R²？

本步驟只驗證輸入表建立正確。下一階段 Step 06B 才會先做簡單基準（分組訓練集 MRR 中位數），再做有方法論的模型比較，而不是直接拿 XGBoost 跑出一個高分數。

## 7. 現階段的資料限制

匿名 Code 1–3、4–6 尚未經證實為不同 Recipe；資料時間戳並非已驗證完整生產順序；有 4 筆極端 MRR、大量時間關聯與少數不完整訊號。建模評估需保留這些限制，並做對照／敏感度分析。
