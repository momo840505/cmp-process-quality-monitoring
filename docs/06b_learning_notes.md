# Step 06B 學習筆記：為什麼要先做基準再訓練模型？

### 1. 不做模型，最簡單能預測到什麼程度？

對每個匿名代碼組，各取 **Training** 的 MRR 中位數。假設 Codes 4–6 的中位數約 73.9，每片 Valid 晶圓就先預測 73.9。不用任何感測資料。這樣能當作比較依據：如果複雜模型連這個方法都比不過，就要重新思考是否有必要導入。

### 2. 模型真正使用了哪些資料？

只使用 Step 06A 白名單中，該代碼組的感測特徵，包括壓力、流量、旋轉、耗材使用量和訊號活動比例；每一片晶圓各一列。`AVG_REMOVAL_RATE` 只能作為訓練答案 Y；`WAFER_ID`、`vm_partition`、`mrr_review_gt_1000` 與時間戳等不可以偷放入 X。

### 3. 為何選擇 HistGradientBoostingRegressor？

這是用一連串小決策樹逐步改善預測的迴歸模型；我們設定 `loss='absolute_error'`，避免少數極端 MRR 過度主導目標函數。它也能接受特徵中的 NaN。本階段是固定參數比較，不是大規模調參。

### 4. 為何一定要看 MAE、RMSE 和 R²？

MAE 可以直觀回答「通常差多少」。RMSE 對極端錯誤更敏感。R² 告訴你模型對資料變異的解釋程度，但極端值可能導致 R² 看起來很差或很怪。所有指標都應先看 **完整 VALID**，再補充一般尺度觀察。

### 5. 為何 Stage A 要分 Codes 1–3 與 Codes 4–6？

先前 Step 03B 發現兩組 MRR 分布和感測活動模式明顯不同；但代碼仍是匿名資訊，**不表示已經知道哪個實體機台或配方**。這只是可審查的分組假設。

### 6. 面試時怎麼說？

「我先用各運作代碼組的訓練 MRR 中位數作為預測基準，再比較使用研磨期間感測資料的梯度提升迴歸模型。過程中把每片晶圓視為一個樣本，並排除晶圓識別碼、品質答案、審查標籤等可能造成洩漏的欄位。模型評估先用 Validation，而不是直接看 Test，並且將四筆極端 MRR 的影響獨立說明。」
